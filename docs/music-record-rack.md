# Music 唱片架

视觉参考是用户提供的 8.6 秒 `bswWD1Hkgar_l8zU.MP4`：左侧应用中的唱片封套翻阅，右侧实体唱片架。没有取得或声称移植该原生 App 的源码；实现依据视频可观察到的空间与动作关系，使用本站已有 Motion、音乐数据和资源。

## 空间与操作

- 首页封面、完整内页共用 `RecordRack.astro`、同一套几何与 21 首曲目。小唱片架支持鼠标拨动、横向触摸拨动；手机竖向手势仍可滚动首页。点击进入完整唱片架。
- 内页使用原生纵向滚动与触摸惯性，鼠标可拖动并续滑，键盘支持上下、Home/End、PageUp/PageDown、Enter/Space。
- 封套按高度排列在透视空间中，穿过视线中线时接近水平、收成侧脊；上下两侧逐渐露出封面。前后面依观看方向翻转，同一张封面/视频保持正向，侧脊与侧边提供厚度。
- 选中后同一封套转正；桌面详情在右侧，手机详情在下方。ParentLink 的返回先放回唱片，再返回 Home。曲目、平台链接和试听地址沿用原数据，没有虚构专辑曲目列表。
- 首页打开/关闭在小架与大架之间插值同一空间，记录位置保留；进入、返回和浏览器前后退可重定向进行中的动画。动态封面的视频节点会实际交接到当前唱片架，保留同一个播放进度。
- 预览封面可直接向下拖回唱片架。封套连续跟随抓取点并翻平，原架逐渐显现；相邻封套让位后合拢。约 52–78px 的慢拖或短促下甩会归槽；短拖、反向拖回、触摸取消和丢失捕获均回到预览，试听继续。只有提交返回时才暂停试听。
- 详情下方的两条真实相邻唱片脊与空槽提供 `Slide back` 操作，也支持点击、Enter/Space。封面本身可点击放回；现有 ParentLink、Esc、浏览器返回保持有效。所有返回共用详情历史，快速双击不会穿透选中后方唱片。

## 模块

| 模块 | 职责 |
| --- | --- |
| `src/lib/record-rack.ts` | 布局、封套姿态、透视投影、点击命中、取出位置及小/大架插值 |
| `src/scripts/record-rack.ts` | 原生滚动、指针/键盘、可中断动画、可见范围和视频生命周期 |
| `src/components/RecordRack.astro` | 共用封套、印字侧脊、实体边缘和滚动吸附点 |
| `src/components/MusicFolder.astro` | 首页唱片架封面及原有标题/数量 |
| `src/components/MusicShowcase.astro` | 原 ParentLink、完整唱片架、原曲目信息、试听及平台入口 |
| `src/scripts/music-rack-page.ts` | 同页历史、详情/浏览切换、首页连续过渡、背景锁与焦点 |

Music 已从通用 Folder 控制器分离，其他文件夹仍使用原控制器。删除了旧 Music 网格和五张预览卡的平面飞行动画；没有新增依赖或图像资源。

## 约束

- Music 的键盘焦点使用当前曲目、操作文字和返回标签的下划线提示；专辑、侧脊、预览封面、按钮及首页入口均不加焦点描边。
- 试听由 Preview 按钮控制，移除旧网格的移入播放、移出暂停，避免抓取封面时打断播放。继续使用 `music-preview.ts` 的单播放器、加载缓存、请求代次取消及浏览器拒播提示。确认归槽、离开详情、关闭内页、切后台均暂停。
- 每个唱片架只有一份动态封面视频；不可见、停用、减弱动态以及视线中线无可见面积时暂停视频。没有 WebGL 场景。
- 每张专辑是闭合六面封套：正反面与四条侧边共享 8 个角点、12 条棱、同一组姿态和厚度。活动封面保留原图/视频，另一面使用现有海报，不复制视频。面与面精确接合，不用额外的浮起偏移拼接厚度。
- 触屏保留同一套角度、间距、滚动与归槽姿态，使用逐面完整投影；场景和卡片父容器保持非退化边界。整个实体按各面外法线统一判断可见性，投影面与侧脊文字不再依赖手机的背面剔除及面内裁切。桌面继续使用原有嵌套 3D 渲染同一个实体模型。
- 内页返回首页时，后方文件夹延后由真实指针移动触发悬停，避免关闭覆盖层产生的布局 pointerenter 误开 Projects；正常移动和点击不被拦截。
- Reduce Motion 保留可浏览内容，去掉自定义续滑和非必要过渡。封套的透明度作用于叶子表面，避免把保留 3D 的父层压平。
- 归槽拖动的投影跟手坐标和意图判断是纯函数；抓取时保留当前动画姿态，取消、旋转屏幕或切后台后复位。详情将集合临时切换为有名称的 group，并隐藏内部视觉 option，避免把返回按钮嵌在 listbox 的选项树中。
- 独立 `/music` 与首页内页保留各自入口；无脚本时提供原平台链接列表。

## 验证

几何、返回导航、文件夹悬停与现有物品架回归共 24 项检查通过；实体检查保证六个面闭合、角点共享、每条棱连接两个面，六面投影与点击模型一致。另覆盖上下区域的侧脊可见性、中线换面与缩放交接。触屏绘制专项检查场景、父层和厚边的有效边界。

Chrome、WebKit 的桌面和 390px 触摸视口验证了翻阅、取出/放回、位置记忆、试听状态、同一视频节点交接、浏览器前后退、连续中断、横屏及 Reduce Motion。320px 详情不溢出，视口高度改变后保留最后一张的位置，关闭内页不误开后方 Projects。试听状态测试使用可控音频替身；另在 Chrome 抽查了实际 Apple Music 试听播放。

归槽新增验收：Chrome 覆盖 1440、1024、768、390、320px；Chrome、WebKit 均检查轻甩、反向取消、丢失捕获、双击保护、快速重新取出及上方封面。Chrome 原生触摸序列检查归槽与取消。短拖期间试听保持，归槽后暂停。

iOS 26.4 Safari 模拟器用 XCTest 以 30px/s 做双向真实慢拖并录屏复核原版造型。用户设备为 iPhone 16 Pro Max / iOS 27；模拟器版本不同，真机结果仍由用户实测确认，不把桌面 WebKit 软件截图等同于 iPhone 画面。

生产构建通过，保留全部 42 个活动开发依赖缓存文件；构建后实际水合首页的 Music、邮件和工具组件也通过检查。浏览器截图及执行记录位于本地开发验收笔记中。实体 iPhone 的渲染、手感及真实音频仍需现场确认。
